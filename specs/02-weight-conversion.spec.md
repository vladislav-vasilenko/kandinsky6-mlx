## Goal

A converter that turns each diffusers component directory (`transformer/`, `vae/`, `audio_vae/`, `vocoder/`) into an MLX-ready safetensors file with the same parameter names, MLX tensor layouts and the project dtype policy. Later specs load models only through its output.

The converter must not depend on MLX, PyTorch or a GPU, so it runs on Linux CPU machines. Real checkpoints are converted on Kaggle (the Mac has too little free disk for source plus output), and the Mac downloads only the converted weights.

## Read first

- MLX docs for `mlx.nn.Conv1d`, `Conv2d`, `Conv3d`, `ConvTranspose1d`: weight layouts are channels-last (`[out, *kernel, in]` for convolutions); confirm the transposed-convolution layout in the installed MLX version.
- The safetensors file format (8-byte header length, JSON header with `dtype`, `shape`, `data_offsets`, then raw data).
- Header dtypes of the real checkpoint (`kandinskylab/Kandinsky-6.0-Lite-distill-5s-Diffusers@4c487e8b`):
  - `transformer`: 1976 BF16 tensors (5.90 GiB) and 423 F32 tensors (0.05 GiB). No convolutions.
  - `vae`, `audio_vae`, `vocoder`, `text_encoder_2`: all F32.
- `audio_vae/diffusion_pytorch_model.safetensors` also stores 667 `vocoder.*` tensors identical to `vocoder/` (see https://huggingface.co/kandinskylab/Kandinsky-6.0-Lite-distill-5s-Diffusers/discussions/3). They must be dropped.
- The study repository's weight snapshot notebooks (`generative-ai-research/kandinsky-6/notebooks/17_kaggle_k6_weights_media.ipynb`, generator `kandinsky-6/scripts/build_weights_snapshot_notebooks.py`): private CPU kernel `applehawk/k6-lite-diffusers-weights-media` already holds the Lite media components at revision `4c487e8b` with SHA-256 verification. Its output is the conversion input on Kaggle.

## Deliverables

- `src/kandinsky6_mlx/convert/convert.py`: `convert_component(src_dir, component, dst_dir, dtype_policy)` and a CLI `python -m kandinsky6_mlx.convert --checkpoint <dir> --out <dir> [--components ...]`. Imports only the standard library, NumPy and `safetensors` (no `mlx`, no `torch`).
- `src/kandinsky6_mlx/convert/layouts.py`: a static table, per component, of parameter-name patterns that are convolution weights with their rank and whether they are transposed convolutions.
- `src/kandinsky6_mlx/utils/dtype_policy.py`: storage modes `checkpoint` (keep every stored dtype) and `float32` (for parity tests), plus `keeps_fp32(component, name)` — the DiT parameters (`time_embeddings`, `modulation`) that run in float32, applied by the MLX loader in spec 05.
- Output per component: `model.safetensors`, `config.json` copied unchanged, `conversion.json` with source revision, source file SHA-256, output SHA-256, tensor count, dropped keys and transposed keys.
- `kaggle/convert/convert_k6.py` and `kaggle/convert/kernel-metadata.json`: a private CPU Kaggle script kernel that converts the Lite media components from the `applehawk/k6-lite-diffusers-weights-media` output and optionally uploads them to a private Hugging Face repository. Generated by `scripts/build_kaggle_convert.py`, which inlines the converter modules into the single kernel script (the GitHub repository is private, so the kernel cannot `pip install` it).
- `tests/unit/test_convert.py`, `tests/unit/test_kaggle_convert_sync.py`.
- `reports/02-weight-conversion.json`.

## Implementation notes

- Name mapping is the identity: MLX modules will mirror diffusers module trees. Any rename needed later is added here, with a test.
- Transpose only convolution weights: Conv1d `[out,in,k] -> [out,k,in]`, Conv2d `[out,in,kh,kw] -> [out,kh,kw,in]`, Conv3d `[out,in,kd,kh,kw] -> [out,kd,kh,kw,in]`; transposed convolutions use the layout confirmed from the MLX docs. Convolutions are found through `layouts.py`, not by tensor rank. A test builds each tiny reference model and checks that the table selects exactly the weights of its `nn.Conv*`/`nn.ConvTranspose*` modules.
- The video VAE `CausalConv3d` wraps an inner `conv`; the parameter path is `...conv.weight`.
- BF16 without PyTorch: NumPy has no bfloat16. Read BF16 tensors as `uint16` bit patterns and write them back with the `BF16` dtype tag (a small writer that emits the safetensors header and raw bytes, or `safetensors` APIs that accept raw buffers). BF16 data must be byte-identical to the source unless the policy casts it.
- Never upcast BF16 tensors to save as F32 in default mode. The Lite DiT stores 268 modulation tensors (549M parameters) as BF16; diffusers upcasts them at load time, and storing them as F32 would add 1.02 GiB with no new information. The MLX loader upcasts them instead.
- Stream tensor by tensor so peak memory stays near the largest tensor, not the file size (Kaggle CPU sessions have about 30 GB RAM; the Lite DiT file is 5.95 GiB, Pro is about 60 GB).
- Kaggle kernel:
  - Inputs: `kernel_sources: ["applehawk/k6-lite-diffusers-weights-media"]`; find the snapshot under `/kaggle/input/` by searching for `transformer/config.json` instead of hard-coding the mount path (the mount path differs between notebook and script kernels).
  - Writes to `/kaggle/working/k6-lite-distill-mlx/` (about 8.5 GiB; `/kaggle/working` has 20 GB).
  - `UPLOAD = False` by default. When `True`, it reads `HF_TOKEN` from Kaggle Secrets and uploads to a private repository (default `VVladTech/Kandinsky-6.0-Lite-distill-5s-MLX`) with a generated model card stating source repository and revision, conversion command, SHA-256 of every file and license (MIT). Kaggle Secrets are only readable in kernels run from the Kaggle editor, not in versions pushed by the CLI; the docstring says so.
  - Never prints or logs the token.

## Tests

- Tiny fixtures: converting the tiny DiT, VAE, audio VAE and vocoder weights produces exactly the parameter names the MLX modules will expect (reference `named_parameters` and persistent buffers), with convolution layouts transposed.
- Layout table coverage: for every tiny reference model, the set of transposed keys equals the set of `nn.Conv*`/`nn.ConvTranspose*` weights.
- Conv1d/Conv2d/Conv3d/ConvTranspose1d round trip: MLX convolution with converted weights equals the torch convolution on the same input (`rel_max <= 1e-5`, float32).
- BF16 pass-through: a synthetic BF16 safetensors file converts with byte-identical tensor data.
- `audio_vae` conversion drops every `vocoder.*` key and keeps all others.
- Dtype policy: a BF16 tiny DiT converts with every stored dtype unchanged; `keeps_fp32` selects `time_embeddings`/`modulation` parameters only; `float32` mode stores exact float32 values.
- Real checkpoint names (header-only, no download): `scripts/check_checkpoint_keys.py` matches every tensor of each component against the reference class built from the checkpoint config on the `meta` device.
- Portability: the converter imports with `mlx` and `torch` made unimportable (`sys.modules` entries set to `None` in a subprocess).
- Generator sync: `scripts/build_kaggle_convert.py --check` passes (the kernel script equals a fresh build).

## Validation runs

```bash
uv run --group reference pytest tests/unit/test_convert.py tests/unit/test_kaggle_convert_sync.py -q
uv run python scripts/build_kaggle_convert.py --check
# Stage B on Kaggle (after the owner approves the GPU-free run; UPLOAD stays False unless approved):
uvx kaggle kernels push -p kaggle/convert
uvx kaggle kernels output applehawk/k6-lite-distill-mlx-convert -p outputs/02 --file-pattern 'conversion.json'
```

Stage B report: tensor counts per component, dropped keys (expect 667 in `audio_vae`), output sizes and SHA-256, wall time, peak RAM, and, if uploaded, the Hugging Face repository and revision.

## Acceptance criteria

- [ ] Stage A tests pass on the Mac and in CI.
- [ ] The converter runs without `mlx` and `torch`.
- [ ] Kernel script is in sync with its generator.
- [ ] Stage B (if run): every component converts on Kaggle; `audio_vae` loses exactly 667 tensors; the DiT keeps 1976 bf16 + 423 f32 tensors; BF16 data byte-identical to the source.

## Out of scope

Quantization (spec 14). Text encoders (spec 11). Public release of weights (spec 15).

## Stop conditions

- A tensor in the real checkpoint does not match any reference parameter name → `FAIL` with the list.
- Uploading to Hugging Face or running a Kaggle kernel: prepare everything, then wait for the owner's explicit approval; these are outward actions.
